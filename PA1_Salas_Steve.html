Descripción General del Proyecto

Contexto, objetivos y estructura del prototipo

El presente informe documenta el desarrollo del Hito 1: Prototipo Funcional 2D y Game Feel, correspondiente al primer producto académico del curso de Desarrollo de Videojuegos. El proyecto se construyó desde cero en Unity 6 (6000.5.10f1) bajo el pipeline de renderizado Universal Render Pipeline 2D (URP), trabajando con física 2D nativa, animaciones por máquina de estados y control de versiones mediante Git y GitHub.

El eje central del hito fue el concepto de Game Feel: esa sensación táctil e inmediata que tiene el jugador al interactuar con el personaje. Se calibraron cuidadosamente velocidad, fuerza de salto y gravedad para eliminar cualquier inercia artificial o "patinaje". El escenario de pruebas concentra todas las mecánicas requeridas en un nivel compacto y funcional.

La arquitectura se organiza en carpetas especializadas: Scripts (lógica C#), Prefab (objetos reutilizables), Scenes (escenario principal), animations (clips y controladores), sprites (atlas del pack "Berie's Adventure") y Music (audio de fondo). El historial de cambios está registrado mediante commits descriptivos y un .gitignore configurado con la plantilla oficial de Unity.

Diseño Físico y Calibración del "Game Feel"

Parámetros de movimiento, salto, detección de suelo e interacciones

El diseño de las físicas partió de un principio central del diseño de videojuegos: la sensación de control inmediato siempre debe priorizarse sobre el realismo físico. Por eso se empleó respuesta instantánea mediante Input.GetAxisRaw, que retorna valores exactos de -1, 0 o 1 sin suavizado. La velocidad se aplica directamente sobre rb2D.linearVelocity, la API actualizada de Unity 6 para el control preciso del Rigidbody2D.

El sistema de salto fue el aspecto más cuidadosamente ajustado. Se descartó AddForce porque generaba variaciones impredecibles dependiendo del peso y fricción del entorno. En su lugar, se asigna directamente la componente Y de linearVelocity, garantizando la misma altura de salto sin importar las condiciones del nivel.

Componente / Mecánica Valor Configurado Decisión de Diseño y Justificación Técnica
Movimiento horizontal speed = 2.0f Velocidad controlable combinada con GetAxisRaw: elimina deslizamiento y aceleración artificial, logrando respuesta táctil inmediata al teclado.
Salto jumpForce = 4.0f Asignación directa en el eje Y de linearVelocity. Garantiza parábola de salto consistente, calibrada para alcanzar las plataformas del nivel.
Gravedad GravityScale = 1.0 Escala estándar de Unity elegida tras pruebas comparativas. Valores mayores aceleraban la caída de forma brusca, afectando la lectura del salto.
Detección de suelo OverlapCircle (r = 0.1) Círculo de colisión en groundCheck (pies del personaje) filtrado por groundLayer. Impide estrictamente el doble salto o salto en el aire.
Barril empujable / plataforma Mass=3.5 · Damping=3.0 Rigidbody2D dinámico en capa Floor (Layer 3). El jugador puede empujarlo con resistencia física sólida, subirse encima y saltar desde su superficie.
Bombas (obstáculos) Knockback = 3.0f Al colisionar se calcula el vector opuesto al impacto y se aplica impulso al jugador. Los colliders se desactivan, el Animator habilita la animación de 9 fotogramas y el objeto se destruye tras 0.5 s.
Monedas (coleccionables) Trigger 2D + TMP_Text Collider marcado como Is Trigger. Al contacto en OnTriggerEnter2D la moneda se destruye, el contador interno sube y la UI de TextMeshPro se actualiza en tiempo real.

Bitácora Digital de Desarrollo

Registro de decisiones técnicas, optimizaciones y metodología de pruebas

A lo largo del desarrollo se tomaron decisiones de ingeniería clave para garantizar estabilidad y rendimiento. La primera fue estructurar el script PlayerController.cs con encapsulamiento formal mediante atributos [SerializeField] privados, permitiendo calibrar los parámetros de físicas y referencias de UI directamente desde el Inspector de Unity sin exponer el estado interno de la clase. Esta práctica sigue los estándares de arquitectura limpia en Unity.

La segunda decisión fue delegar la detección física de suelo al ciclo de FixedUpdate() en lugar de Update(). Dado que FixedUpdate opera sincronizado con el motor de físicas de Unity a intervalos fijos de tiempo (50 Hz), se evitan discrepancias de colisión causadas por variaciones en la tasa de cuadros por segundo (FPS) del hardware.

Metodología de Pruebas y Depuración Visual

Para optimizar la precisión de los saltos y el contacto con plataformas dinámicas como el barril, se implementó el método OnDrawGizmosSelected(). Esta función proyecta una esfera verde de alambre en la ventana de Scene del editor, facilitando la calibración visual del radio de detección (groundRadius = 0.1f) en tiempo real.

Resultado alcanzado: Se logró un prototipo 2D responsivo y consistente, con control total en el aire, eliminación completa del salto infinito y una respuesta física sólida en todas las interacciones del nivel.

PlayerController.cs — Controlador Principal del Jugador

209 líneas · Encapsulamiento formal con [SerializeField] · Compatibilidad con Unity 6 linearVelocity API

using UnityEngine;
using TMPro;
using UnityEngine.SceneManagement;

/// ===========================================================================
/// PROYECTO : Hito 1 — Prototipo Funcional 2D y Game Feel
/// SCRIPT   : PlayerController.cs
/// GESTIONA : Movimiento, salto, detección de suelo, animaciones e interacciones
/// ===========================================================================
public class PlayerController : MonoBehaviour
{
    // BLOQUE 1 — Variables serializadas (configurables desde el Inspector)

    [Header("--- PARÁMETROS DE MOVIMIENTO Y GAME FEEL ---")]
    [Tooltip("Velocidad horizontal en unidades Unity/segundo")]
    [SerializeField] private float speed = 2f;

    [Tooltip("Fuerza del impulso vertical al saltar")]
    [SerializeField] private float jumpForce = 4f;

    [Header("--- DETECCIÓN FÍSICA DE SUELO ---")]
    [Tooltip("Transform vacío ubicado en los pies del personaje")]
    [SerializeField] private Transform groundCheck;

    [Tooltip("Radio del círculo de detección de suelo")]
    [SerializeField] private float groundRadius = 0.1f;

    [Tooltip("Capa que define superficies caminables")]
    [SerializeField] private LayerMask groundLayer;

    [Header("--- INTERFAZ DE USUARIO ---")]
    [Tooltip("Texto TextMeshPro del contador de monedas")]
    [SerializeField] private TMP_Text TextCoins;

    // BLOQUE 2 — Componentes y variables de estado internas
    private Rigidbody2D rb2D;     // Motor de física 2D (velocidad, gravedad)
    private Animator animator;    // Máquina de estados de animaciones
    private float move;           // Input: -1 (izq), 0 (quieto), 1 (der)
    private bool isGrounded;      // ¿El personaje toca el suelo?
    private int coins = 0;        // Contador de monedas recolectadas

    // BLOQUE 3 — Start: inicialización de componentes al cargar la escena
    void Start()
    {
        rb2D     = GetComponent<Rigidbody2D>();
        animator = GetComponent<Animator>();
    }

    // BLOQUE 4 — Update: lectura de teclado, movimiento, salto y animaciones
    void Update()
    {
        // 4.1 Input sin inercia (GetAxisRaw devuelve exactamente -1, 0 o 1)
        move = Input.GetAxisRaw("Horizontal");

        // 4.2 Velocidad horizontal directa; conserva la velocidad vertical Y
        rb2D.linearVelocity = new Vector2(move * speed, rb2D.linearVelocity.y);

        // 4.3 Flip del sprite según la dirección de avance
        if (move != 0)
            transform.localScale = new Vector3(Mathf.Sign(move), 1, 1);

        // 4.4 Salto — solo si el personaje está en el suelo (evita doble salto)
        if (Input.GetButtonDown("Jump") && isGrounded)
            rb2D.linearVelocity = new Vector2(rb2D.linearVelocity.x, jumpForce);

        // 4.5 Sincronización de parámetros con el Animator
        if (animator != null)
        {
            animator.SetFloat("Speed",            Mathf.Abs(move));
            animator.SetFloat("VerticalVelocity", rb2D.linearVelocity.y);
            animator.SetBool ("IsGrounded",        isGrounded);
        }
    }

    // BLOQUE 5 — FixedUpdate: detección física de suelo (ciclo de física fijo)
    void FixedUpdate()
    {
        if (groundCheck != null)
            isGrounded = Physics2D.OverlapCircle(
                groundCheck.position, groundRadius, groundLayer);
    }

    // BLOQUE 6 — OnTriggerEnter2D: colisiones e interacciones con el escenario
    private void OnTriggerEnter2D(Collider2D collision)
    {
        // 6.1 Moneda — destruye el objeto, suma al contador y actualiza la UI
        if (collision.CompareTag("Coin"))
        {
            Destroy(collision.gameObject);
            coins++;
            if (TextCoins != null) TextCoins.text = coins.ToString();
        }

        // 6.2 Pinchos — reinicia la escena activa de forma inmediata
        if (collision.CompareTag("Spikes"))
            SceneManager.LoadScene(SceneManager.GetActiveScene().name);

        // 6.3 Bomba/Barril — knockback + animación de explosión + destrucción
        if (collision.CompareTag("Barrel") || collision.CompareTag("Bomb"))
        {
            Vector2 dir = (rb2D.position - (Vector2)collision.transform.position)
                          .normalized;
            rb2D.linearVelocity = Vector2.zero;
            rb2D.AddForce(dir * 3f, ForceMode2D.Impulse);

            foreach (var col in collision.gameObject.GetComponents<BoxCollider2D>())
                col.enabled = false;

            if (collision.TryGetComponent(out Animator anim))
                anim.enabled = true;

            Destroy(collision.gameObject, 0.5f);
        }
    }

    // BLOQUE 7 — OnDrawGizmosSelected: guía visual del radio de suelo en editor
    private void OnDrawGizmosSelected()
    {
        if (groundCheck != null)
        {
            Gizmos.color = Color.green;
            Gizmos.DrawWireSphere(groundCheck.position, groundRadius);
        }
    }
}
