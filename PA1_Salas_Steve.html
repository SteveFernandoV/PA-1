Descripción General del Proyecto

Contexto, objetivos y estructura del prototipo

El presente informe documenta el desarrollo del Hito 1: Prototipo Funcional 2D y Game Feel, correspondiente al primer producto académico evaluado del curso de Desarrollo de Videojuegos. El proyecto consistió en construir desde cero un prototipo jugable en Unity 6 (6000.5.10f1) bajo el paradigma de renderizado Universal Render Pipeline 2D (URP), trabajando con física 2D nativa, animaciones por máquina de estados y control de versiones mediante Git.

El eje central del hito fue el concepto de Game Feel: esa percepción táctil e inmediata que tiene el jugador al interactuar con el personaje. Para lograrlo, se calibraron cuidadosamente los parámetros de velocidad, fuerza de salto y gravedad, eliminando cualquier sensación de inercia artificial o "patinaje" al moverse. El escenario de pruebas —denominado internamente "El Laboratorio de Movimiento"— concentra todas las mecánicas exigidas por la rúbrica en un solo nivel compacto y funcional.

La arquitectura del proyecto se organiza en carpetas especializadas: Scripts (lógica en C#), Prefab (objetos reutilizables), Scenes (escenario principal), animations (clips y controladores de animación), sprites (atlas gráfico del pack "Berie's Adventure") y Music (audio ambiental de fondo). Todo el historial de cambios está registrado en el repositorio oficial a través de commits descriptivos y un archivo .gitignore configurado con la plantilla oficial de Unity.

Diseño Físico y Calibración del "Game Feel"

Parámetros de movimiento, salto, detección de suelo e interacciones

El diseño de las físicas del personaje partió de un principio fundamental del diseño de videojuegos: la sensación de control inmediato siempre debe priorizarse sobre el realismo físico. Por eso, en lugar de aplicar una curva de aceleración natural, se optó por respuesta instantánea usando Input.GetAxisRaw, que retorna valores exactos de -1, 0 o 1 sin suavizado. La velocidad se aplica directamente sobre rb2D.linearVelocity, la API actualizada de Unity 6 para el control preciso de la velocidad del Rigidbody2D.

El sistema de salto fue uno de los aspectos más cuidadosamente ajustados. Se descartó el uso de AddForce para el salto porque generaba variaciones impredecibles dependiendo del peso y la fricción del suelo. En su lugar, se asigna directamente la componente Y de linearVelocity, garantizando siempre la misma altura de salto sin importar las condiciones del entorno.

Componente / Mecánica Valor Configurado Decisión de Diseño y Justificación Técnica
Movimiento horizontal speed = 2.0f Velocidad pausada y controlable. Combinada con GetAxisRaw elimina cualquier deslizamiento o aceleración artificial, logrando respuesta táctil inmediata al teclado.
Salto jumpForce = 4.0f Asignación directa sobre el eje Y de linearVelocity. Garantiza una parábola de salto consistente y predecible, calibrada para alcanzar las plataformas del nivel.
Gravedad del personaje GravityScale = 1.0 Escala de gravedad estándar de Unity, elegida tras pruebas comparativas. Valores mayores aceleraban la caída de forma brusca, afectando negativamente la lectura del salto.
Detección de suelo OverlapCircle (r = 0.1) Círculo de colisión ubicado en el objeto groundCheck (pies del personaje), filtrado por la groundLayer. Impide de manera estricta el doble salto o el salto en pleno aire.
Barril empujable / plataforma Mass=3.5 · Damping=3.0 Rigidbody2D dinámico asignado a la capa Floor (Layer 3). Permite al jugador empujarlo con resistencia física sólida, subirse encima y saltar desde su superficie, añadiendo variedad estratégica al nivel.
Bombas (obstáculos destructibles) Knockback = 3.0f Al colisionar, se calcula el vector de dirección opuesto al impacto y se aplica un impulso sobre el jugador. Los colliders del obstáculo se desactivan, el Animator de la bomba se habilita reproduciendo la animación de 9 fotogramas, y el objeto se destruye tras 0.5 segundos.
Monedas (coleccionables) Trigger 2D + TMP_Text Collider configurado como Is Trigger. Al detectarse contacto en OnTriggerEnter2D, la moneda se destruye, el contador interno se incrementa y la UI de TextMeshPro se actualiza en tiempo real.

Bitácora Digital de Desarrollo

Registro de decisiones técnicas y transparencia en el uso de IA

A lo largo del desarrollo se tomaron varias decisiones técnicas relevantes que vale la pena registrar. La primera fue migrar el script original player.cs (heredado del proyecto base) a una nueva clase PlayerController.cs con encapsulamiento formal mediante [SerializeField], lo que permitió ajustar todos los parámetros de físicas directamente desde el Inspector de Unity sin necesidad de recompilar el código en cada iteración. Esta práctica es considerada una buena práctica estándar en el desarrollo profesional de videojuegos.

La segunda decisión fue separar la detección de suelo en FixedUpdate() en lugar de hacerla en Update(). Esto se debe a que FixedUpdate está sincronizado con el motor de físicas de Unity, ejecutándose a intervalos constantes de tiempo fijo (50 veces por segundo), mientras que Update depende del framerate variable del hardware. Hacer la detección en el ciclo incorrecto puede causar falsos positivos de colisión a altas velocidades.

Declaración de Uso de Inteligencia Artificial

En apego a las directrices éticas del curso, se declara el uso de asistencia de IA para apoyo en la arquitectura y documentación del código:

"Optimizar la arquitectura del script PlayerController en C# para Unity 6 aplicando buenas prácticas de encapsulamiento con [SerializeField], documentación pedagógica bloque por bloque, detección de suelo con OverlapCircle y compatibilidad con la API linearVelocity de Unity 6."

Adaptación realizada: El código generado fue revisado, corregido manualmente y enriquecido con la lógica específica del proyecto (manejo de tags personalizados, capa Floor para el barril, sincronización con el Animator de las bombas y el contador de TextMeshPro). El diseño de niveles, la selección de assets gráficos y la calibración de Game Feel fueron realizados íntegramente de forma manual en Unity.

PlayerController.cs — Controlador Principal del Jugador

Unity 6 · C# · 209 líneas · Documentado bloque por bloque

using UnityEngine;
using TMPro;
using UnityEngine.SceneManagement;

/// ===========================================================================
/// PROYECTO : Hito 1 - Prototipo Funcional 2D y Game Feel
/// SCRIPT   : PlayerController.cs
/// GESTIONA : Movimiento, salto, detección de suelo, animaciones e interacciones
/// ===========================================================================
public class PlayerController : MonoBehaviour
{
    // BLOQUE 1 — Variables serializadas (configurables desde el Inspector)

    [Header("--- PARÁMETROS DE MOVIMIENTO Y GAME FEEL ---")]
    [Tooltip("Velocidad horizontal en unidades Unity/segundo")]
    [SerializeField] private float speed = 2f;

    [Tooltip("Fuerza del impulso vertical al saltar")]
    [SerializeField] private float jumpForce = 4f;

    [Header("--- DETECCIÓN FÍSICA DE SUELO ---")]
    [Tooltip("Transform vacío ubicado en los pies del personaje")]
    [SerializeField] private Transform groundCheck;

    [Tooltip("Radio del círculo de detección de suelo")]
    [SerializeField] private float groundRadius = 0.1f;

    [Tooltip("Capa que define superficies caminables")]
    [SerializeField] private LayerMask groundLayer;

    [Header("--- INTERFAZ DE USUARIO ---")]
    [Tooltip("Texto TextMeshPro del contador de monedas")]
    [SerializeField] private TMP_Text TextCoins;

    // BLOQUE 2 — Componentes y variables de estado internas
    private Rigidbody2D rb2D;     // Motor de física 2D (velocidad, gravedad)
    private Animator animator;    // Máquina de estados de animaciones
    private float move;           // Input: -1 (izq), 0 (quieto), 1 (der)
    private bool isGrounded;      // ¿El personaje toca el suelo?
    private int coins = 0;        // Contador de monedas recolectadas

    // BLOQUE 3 — Start: inicialización de componentes
    void Start()
    {
        rb2D     = GetComponent<Rigidbody2D>();
        animator = GetComponent<Animator>();
    }

    // BLOQUE 4 — Update: entrada de teclado, movimiento, salto y animaciones
    void Update()
    {
        // 4.1 Lectura de teclado sin inercia (GetAxisRaw devuelve -1, 0 o 1)
        move = Input.GetAxisRaw("Horizontal");

        // 4.2 Velocidad horizontal directa; conserva la velocidad vertical (Y)
        rb2D.linearVelocity = new Vector2(move * speed, rb2D.linearVelocity.y);

        // 4.3 Flip del sprite según la dirección de avance
        if (move != 0)
            transform.localScale = new Vector3(Mathf.Sign(move), 1, 1);

        // 4.4 Salto — solo si el personaje está en el suelo (evita salto infinito)
        if (Input.GetButtonDown("Jump") && isGrounded)
            rb2D.linearVelocity = new Vector2(rb2D.linearVelocity.x, jumpForce);

        // 4.5 Sincronización de parámetros con el Animator
        if (animator != null)
        {
            animator.SetFloat("Speed",           Mathf.Abs(move));
            animator.SetFloat("VerticalVelocity", rb2D.linearVelocity.y);
            animator.SetBool ("IsGrounded",        isGrounded);
        }
    }

    // BLOQUE 5 — FixedUpdate: detección física de suelo (ciclo de física fijo)
    void FixedUpdate()
    {
        if (groundCheck != null)
            isGrounded = Physics2D.OverlapCircle(
                groundCheck.position, groundRadius, groundLayer);
    }

    // BLOQUE 6 — OnTriggerEnter2D: colisiones e interacciones con el escenario
    private void OnTriggerEnter2D(Collider2D collision)
    {
        // 6.1 Moneda — destruye el objeto, suma al contador, actualiza UI
        if (collision.CompareTag("Coin"))
        {
            Destroy(collision.gameObject);
            coins++;
            if (TextCoins != null) TextCoins.text = coins.ToString();
        }

        // 6.2 Pinchos — reinicia la escena activa inmediatamente
        if (collision.CompareTag("Spikes"))
            SceneManager.LoadScene(SceneManager.GetActiveScene().name);

        // 6.3 Bomba/Barril — knockback + animación de explosión + destrucción
        if (collision.CompareTag("Barrel") || collision.CompareTag("Bomb"))
        {
            Vector2 dir = (rb2D.position - (Vector2)collision.transform.position)
                          .normalized;
            rb2D.linearVelocity = Vector2.zero;
            rb2D.AddForce(dir * 3f, ForceMode2D.Impulse);

            foreach (var col in collision.gameObject
                                         .GetComponents<BoxCollider2D>())
                col.enabled = false;

            if (collision.TryGetComponent(out Animator anim))
                anim.enabled = true;

            Destroy(collision.gameObject, 0.5f);
        }
    }

    // BLOQUE 7 — OnDrawGizmosSelected: guía visual del radio de suelo en editor
    private void OnDrawGizmosSelected()
    {
        if (groundCheck != null)
        {
            Gizmos.color = Color.green;
            Gizmos.DrawWireSphere(groundCheck.position, groundRadius);
        }
    }
}
